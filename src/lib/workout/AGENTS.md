- CHALLENGE uses challengeBalanceViolation for full-body, majority-bodyweight, on-level benchmarks; filterPool prefers smarty_tags — why: consistent challenge structure.
- Difficulty is prescription-only; beginners exclude advanced rows. flowSpecialtyViolation bans balance tools/isolation machines in flow/timed formats in pool and validator — why: one WOD/custom engine.
- Closed exercise lists, all read by rules.ts: Activation/Cool Down named lists (prep-vocabulary.ts), Pilates, Mobility & Stability, Recovery (*-vocabulary.ts) — why: generator, pool, publish gate and audit share one rule.
- All workout rules (exercise legality per section, workout structure, dose, duration) are decided only in src/lib/workout/rules.ts (built on doctrine.ts + prep-vocabulary.ts); the pool filter, validator and smarty-compliance audit all call it — why: one rule layer, so no check can apply half the rules.
- Stored-workout repairs go through planMigration in src/lib/workout/smarty-compliance.ts; bannedSwap blocks unsafe substitutes — why: one repair path on the one rule engine, reversible via the pre-migration backup table.
- Strength/Muscle Building focus legality lives only in strength-focus.ts: movement group = coach classification (priority.ts) → library target muscle → name regex, plus a per-focus library-muscle allowlist (muscleFocusBreak); doctrine focusViolation, complianceIssues and the validator all call it — why: an exercise enters a focus only when the library says it trains those muscles.
- No exercise or variant (movementKey) repeats across Activation / Main / Finisher (section-repeats.ts), checked by the publish gate, validator and generator rebuild loop; the pack builder excludes main movements from finisher and activation picks — why: one rule for every workout source.
- Injuries & limitations are rule level 1 in limitations.ts (BLOCKED/RESTRICTED/ALLOWED from movement traits), called by rules.ts, pool, validator and manual save; medical restrictions need member-reported clearance — why: no pathway can bypass safety.
- Finisher length and format (level minimum, honest stated time, approved format chosen deterministically by chooseFinisherFormat) live only in finisher-length.ts, used by the planner, pack builder, complianceIssues gate and repairs — why: one rule decides how long a Finisher is, which approved format it uses and that its stated time adds up.

- Exercise usage cap (fair share per category) lives only in exercise-usage.ts; the generator passes overused ids to the pack builder — why: no single exercise dominates the library.
- Member-built workout quality (focus coverage, selected-equipment share, Advanced vocabulary, level minimum count, no repeated movement, matching cool-down) lives in member-quality.ts; the pack builder picks with it and generate.server.ts rebuilds up to 6 seeds before delivery — why: members get a session that matches what they asked for, without widening any closed list.
- Exercise sameness (movementKey, member-quality.ts) and muscle spread / specific-muscle requests (muscle-spread.ts) take the workout focus; pool filter, pack builder and member final check call them — why: a specific muscle wins, broad focuses cover every muscle.
